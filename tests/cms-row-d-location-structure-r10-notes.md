## Composition with the existing official runner

Import is inert. `runLocationStructure` calls the actual public
`runCmsRowDLive`; it does not copy its guard, keeper or cleanup. Its connect
decorator forwards the exact observer/options, every non-evaluate command,
send options and close. Only the official single `Runtime.evaluate` expression
is replaced, after checking all strict flags and the original expression.

The original inspector executes first. The extra pure function then returns
structure alongside the original inspection. The inspection object is passed
unchanged to the official `cleanInspection`; original ok/reason/fields and
the final verdict retain the official semantics. The extra path never reads
text, answers or referenced list contents. The official inspector's existing
public metadata checks still execute exactly as before.

`exceptionDetails` is returned unchanged. Invalid envelopes fail the official
inspection stage. A strict rejection cannot recover a cached original result,
retry loosely, or start a second evaluation. A diagnostic/schema failure
cannot manufacture a successful inspection. The original official evidence
is retained even when no diagnostic can be saved.

The tool awaits the runner's complete finally/cleanup. A sidecar additionally
requires probeCompleted, all four allowed/ready keeper checkpoints, allowed
original reason, exact Never-Save flags, focus override cleared and a clean
official terminal traffic assessment (no response, command failure or
truncation). Final correlation cannot reopen an early inspection stop.

## Structural scope and bounds

The extra function checks the exact full fixed `ROW_D_PAGE` href before any
tree query. Query/hash variants and navigation fail closed for this extra
diagnostic; the official inspector's own URL rules are not changed.

Only section13 and wrappers `13_100701_0`/`13_100702_0` are diagnosed. Both host
slots are retained whenever the scope has exactly two owned hosts. The output
contains fixed reason enums, bounded counts and booleans for:

- unique section/wrapper/item, peer hosts and shared cascader ancestry;
- one owned combobox/selection and hidden text input per host;
- ARIA reference cardinality and exact in-memory ID association;
- unique owner, exact ID match, list class/role and portal/foreign-scope checks.

No raw token is interpolated into a selector or serialized. Duplicate tokens
on one surface remain ambiguous even when deduplication would leave one ID.
Multiple owners, missing/unmounted lists and foreign scopes remain missing
evidence. List children and option labels/counts are not inspected. No labels,
input state, selected display, placeholder, dynamic aria-label, HTML, profile,
request body or user URL is output. `levelHint=unknown`,
`dictionaryComplete=false` and `optionLabelsExposed=false` are fixed. A
`linked_structure_observed` reason concerns only the graph; it grants no
field/preflight/support permission.

All NodeLists are read through length/indexes, with no page iterator,
matches/closest/contains, layout calls or trim shim. Local selector results
are capped256; global ID/selector/ARIA inventories10000; raw ARIA/style strings
2048 characters; token lists8. Every ancestor traversal uses one shared
128-node cap, including scope, containment, named-wrapper, hidden-input and
portal checks. Over-limit/exception returns only a fixed failure and discards
partial rows. A strict output schema rejects unknown keys, counts above256,
semantic upgrades, wrong/missing host slots and inconsistent observed graphs.

## CLI and evidence files

The parent must review the final source, merge/sync it, recheck its fixed hash,
then invoke once with the actual merged DevTIP and a new directory, for example:

```powershell
$env:PORT='9242'
node scripts/live/cms-row-d-location-structure.mjs --tip <ACTUAL_MERGED_DEV_TIP> --outdir _temp-scripts/cms-row-d-location-structure-<NEW_UNIQUE_SUFFIX>
```

This is documentation, not a live action taken by the implementation worker.
The CLI requires the exact external `TIP_SHA.txt` and the four current vetted
raw dependency hashes before connection and again before sidecar retention.
The two existing Dev scripts currently have CRLF bytes; the CDP/error modules
have LF bytes. Pins deliberately check those exact existing bytes rather than
normalizing or rewriting shared files. The historical embedded baseTip is
never used as this assertion. REQUESTS_FILE/profile/answer overrides are not
accepted. The directory must be a new direct child of the confined
`_temp-scripts` root, reserved atomically; outputs use exclusive writes.

`cms-row-d-live.json` preserves the actual official result, including an early
stop. `structure.json` is written only after the complete final guard and
unchanged source pin checks. No sidecar is kept after guard/cleanup/strict/
schema/source failure. Only fixed redacted status is printed; exception text
is not logged. Exit2 is intentional for this evidence preparation tool; it
does not turn the existing incomplete probe into PASS. No retry/open/click or
calendar gate change is implemented.
