# Generic date controls: detect, plan and readback

Base: `ee515bfd7469bd3664e95869de96cad757d73cee` (#232). These first-party L1 contracts use control type, library/model ownership and explicit format evidence. They contain no tenant URLs, resume-field IDs, field mappings or LLM identification. Calendar observations from particular sites are phenomenon references only.

| Control | Detect contract | Plan contract | Readback contract |
| --- | --- | --- | --- |
| HTML date / month | Actual `input.type` agrees with its declared `date` / `month` attribute; native ownership only. A downgraded or framework-owned input cannot become native text. | Exact `YYYY-MM-DD` / `YYYY-MM`; real Gregorian date, years 1900–2100. Enforce HTML min/max and step, measured in days/months with min, initial value or epoch as the step base. Malformed constraints stay manual. | HTML input `value` is the authoritative public value, sampled twice through the shared verifier. No separate application model or backend acceptance is claimed. |
| My97 date / local datetime | Native-owned editable text input with a My97 marker, callable page `WdatePicker`, and exactly one literal `onfocus` or `onclick` expression `WdatePicker({dateFmt:'…'})`. The parser reads attributes and never evaluates handlers or invokes the picker. | Reviewed formats: `yyyy-MM-dd`, `yyyy-MM-dd HH:mm`, `yyyy-MM-dd HH:mm:ss`. Facts are respectively `YYYY-MM-DD`, `YYYY-MM-DDTHH:mm`, `YYYY-MM-DDTHH:mm:ss`; time is local, without timezone conversion. Validate exact precision, real date and time. Display datetime uses a space. | My97's public input value is authoritative; canonical and exact display values must agree across both samples. Hidden mirrors, framework models and server persistence are unconfirmed. Invalid existing display shapes remain manual. |
| Ant Design Vue 1 month | Vue 2 owning `AMonthPicker`, page library major 1 and exactly one value input. Resolve the stable public owner even when Vue changes the root instance during navigation. Read the effective display format from the rendered component. | Require display `YYYY-MM`. Explicit `valueFormat="YYYY-MM"` consumes a string; absent valueFormat consumes an empty or valid Moment model and serializes to month precision. Reject unexpected model kinds and unknown formats. Write only through the calendar UI, with one newly opened visible panel, verified year, exactly twelve month cells and enabled target. Recheck ownership, version, formats and writable state before effects. | Compare visible input text with the public component model serialized as `YYYY-MM`, twice. DOM-only or model-only changes mismatch; a later change returns reverted. No string emit or raw input assignment fallback for MonthPicker. |

Detection and planning are passive. The registry's existing write opt-in and per-effect checks remain in force. Writers preserve different nonempty values and refuse readonly/disabled controls. Native and editable My97 writers use the existing checked input/change/blur event path; My97 never opens its calendar. Readonly My97, dynamic configuration, callbacks, cross-target `el`, unsupported formats and unreviewed constraints stay manual. Unknown date surfaces use `date-unknown`, above plain text and below confirmed date adapters, so unknown controls cannot silently become text writes.

The shared MAIN inventory includes the date module, internal/paid package allowlists include its bytes, and the default-off ordinary route discovers confirmed native date/month, My97 date/datetime and Ant month candidates. Fact resolution still uses the existing confirmed-profile path. This work adds no schema guessing or datetime fact synthesis; a matching confirmed fact must already exist.

`tests/zoo/dates.spec.mjs` adds seven loopback cases: passive detection/default gate, native precision and constraints, synthetic editable My97 date/datetime, unknown/manual My97, real pinned Ant 1.7.8 default Moment and explicit string models, and unsupported Ant display format. The My97 fixture is a first-party contract replay, not a distribution of the library or proof of live compatibility. Tests execute exact built bytes in disposable browser worlds, locally fulfill every request, preserve neighbors, and check mismatch/reversion and safety evidence. The legacy zoo baselines remain unchanged; the L1 unknown-Ant-version check now explicitly expects manual through `date-unknown`.

Run the focused Node tests with `node --test tests/l1-native-dates.test.mjs tests/l1-date-controls.test.mjs tests/l1-model.test.mjs tests/l1-vue-controls.test.mjs tests/l1-registry.test.mjs tests/l1-write-route.test.mjs`, build with `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-internal.ps1`, then run `npm run test:zoo` (or append `-- dates.spec.mjs` for the new cases).

Never-Save guard policy and `throwOnSideEffect` are untouched. No real save/submit, live recruiting-page run or commercial-record update is part of this change. `liveSupportClaimed=false` throughout.
