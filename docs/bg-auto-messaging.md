# Background timeout for paid auto pages

`CMS_BASIC_AUTO`, `GTH_BASIC_AUTO`, and the sibling auto pages used to `await chrome.runtime.sendMessage` with no deadline. If the MV3 service worker is not running, that promise can stay pending: the page remains on 「正在请求后台 …」, `reportPort` gets no `/result`, and `lastReport` stays null until the runner's 180s timeout. No `service_worker` target fits this; opening the popup does not settle an already pending call.

`worker.mjs` imports `src/background/bg-ping.mjs` first. That module registers `BG_PING` and the `bg-wake` port while it evaluates. The page connects `bg-wake`, then pings. If ping does not succeed within 15s, the page POSTs `{ok:false, reason:"BG_NO_RESPONSE", phase:"ack", helpNeeded:false, writeAttempted:false, saveAttempted:false, messageType, mode, timeoutMs}` and does not send the auto job. After a pong (or a worker that simply ignores ping), the auto message may run up to 160s so a real fill is not cut off ahead of the 90s/120s basic-job budgets. A missing `sendResponse` posts the same reason with `phase:"response"` and `writeUnconfirmed:true`. `BG_PING` answers `{ok:true, reason:"BG_PONG"}`. No Save/Submit and no new site logic.
